## 本轮确认并修复的问题

| 问题 | 复现方式与影响 | 修复 |
| --- | --- | --- |
| 运行中视频取消失败仍留下取消标记 | 模拟引擎请求失败，接口返回失败，但 task.canceled/job.cancelRequested 已被设置，后续任务会误判状态 | 引擎确认后才设置标记；任务结算等待进行中的取消请求 |
| AI 工具取消吞掉引擎错误 | 引擎不可达时仍返回成功，并将任务置为取消 | 正确返回失败，保留原运行状态，允许重试取消 |
| 批量抠图取消失败仍终止批次 | 取消请求失败，但 batch.canceled/task.canceled 已为 true | 复用确认式取消；批次等待取消请求结算后再分类与进入下一项 |
| 迟到的取消覆盖新任务引用 | 取消旧任务期间切换 activeTask，旧处理器结束后会清空新任务，并用新任务 ID 发出取消进度 | 只操作捕获的任务对象，固定原 jobId，不清空共享新任务引用 |
| 并发重试重复提交并覆盖素材 | 两次重试均等待恢复输入，第二次恢复完成后仍覆盖第一次已提交的任务并再次启动处理 | 恢复先在局部变量完成，提交前检查任务所有权、状态和输入版本；冲突时拒绝并清理本次临时副本 |
| 恢复素材期间删除后仍报告重试成功 | 任务在异步恢复素材时被删除，恢复结束仍调用处理并返回成功 | 提交前确认原任务仍在队列中，删除后不重新启动 |
| 素材库删除保存失败时界面先丢条目 | 注入保存失败，素材库条目已从 React 状态移除 | 保存成功后才更新界面与清理文件；异常显示错误 |
| 素材库配置只检查外层数组 | API 可以保存 [null]、数字条目或错误字段类型，后续界面操作可能报错 | 保存与加载都检查条目结构，拒绝无效数据并保留原配置 |
| AI 工具之间的进度相互覆盖 | 抠图运行时发出图像理解进度，抠图进度条会显示识图文本与百分比 | 按当前工具 kind 过滤事件，切换工具清除旧进度 |

以上故障已通过隔离测试复现，不是仅依据静态代码推测。修复后增加取消确认、重复取消、失败后再取消、准备阶段停止、队列终态竞态和原任务引用保护等检查。
