本轮在 1.1.20 全软件检查基础上继续检查任务队列、CLI/HTTP、取消竞态、工作流备份与文件保存，并重新验证所有页面。此前检查详见 `WHOLE-APP-AUDIT-1.1.20.md`。

## 本轮发现并修复

| 问题 | 已复现的影响 | 修复方式 |
| --- | --- | --- |
| 队列修改未检查保存结果 | 移除、清空、重排、重试、取消在写入失败时仍返回成功，重启后状态与界面不一致 | 检查写入结果，失败恢复原队列和任务字段，不启动重试任务 |
| 队列清理提前删除输入 | 移除或清空先清输入，再保存；保存失败后磁盘上仍有任务却丢失输入 | 先保存新队列，成功后清理输入；失败保留记录和素材 |
| HTTP 取消与桌面逻辑不一致 | HTTP 独立实现取消，忽略队列保存失败 | 共用桌面取消处理器，正确向 CLI/API 返回失败 |
| 取消失败和任务完成的竞态 | 工具任务已完成，但尚未返回的取消请求失败，记录仍可能误为已取消 | 等待取消结果后结算任务；取消失败移除取消标记，保留完成结果 |
| 重复取消调用底层多次 | 两个同时到达的取消请求会重复调用模型取消接口 | 同一个任务共用进行中的取消请求；失败后可重试；同时覆盖同步异常处理 |
| 损坏任务历史校验不完整 | 重复 ID、未知状态、缺少类型、空 ID 被当作正常记录读取 | 拒绝无效记录，保留原文件，后续读取也不会静默覆盖 |
| 工作流备份可以恢复到其他工作流 | 将图生视频备份 ID 传入文生视频恢复接口，能够覆盖文生配置 | 检查备份文件名与工作流归属；恢复采用原子写入 |
| HTTP 空值参数被静默替换 | 显式传入 null、false、0 或空字符串，会被当作空对象提交 | 仅省略 input 时补默认值，显式无效参数返回错误 |
